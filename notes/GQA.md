# KV Cache

## LLM 如何生成文字

假设模型要生成：

> 我喜欢吃苹果

​

```
第1步：
输入“我”
→ 预测“喜欢”

第2步：
输入“我 喜欢”
根据“喜欢”的 Q 计算注意力得到隐藏状态
→ 预测“吃”

第3步：
输入“我 喜欢 吃”
根据“吃”的 Q 计算注意力得到隐藏状态
→ 预测“苹果”
```

也就是说，每生成一个新 token，就要利用前面所有的 token

生成下一 token 时，计算的是“当前已有的最后一个 token”的 QKV，然后用当前 Q 去查询历史 K/V Cache，得到当前隐藏状态，再预测下一个 token。

Q 查询的是：

> **“当前这个位置，为了预测下一个 token，我应该从历史上下文中提取什么信息？”**

### 实际上的流程：

根据最后一个位置经过多层 Transformer 后得到的上下文表示，来预测下一个 token。

```
最后一个 token
      ↓
Embedding
      ↓
Transformer 第1层
      ↓
Transformer 第2层
      ↓
...
      ↓
Transformer 第N层
      ↓
最后位置的隐藏状态
      ↓
LM Head
      ↓
下一个 token 的概率
```

# 自回归(Autoregressive)生成

上面全部串起来就是自回归生成

```
历史 token
   ↓
Q K V
   ↓ KV Cache 存储
Attention
   ↓
最后位置的上下文表示
   ↓
预测下一个 token
   ↓
新 token 加进来
   ↓
继续预测 -> 重复
```

# MHA(Multi-Head Attention)

普通的 attention 可以理解成一个 KQV 做运算，但是 Transformer 要同时做好几组，来学习不同的关系

比如：

```python
num_attention_heads = 8 #模型内的注意力头数
```

这个模型就有 Head 0 到 Head 7 的八个注意力头

每个注意力头都有自己的 KQV

就可以学习到语句中不同的关系

例如一句：

> 小明昨天去了北京，他在那里吃了烤鸭。

```
Head 1：小明 <-> 他
Head 2：去了 <-> 北京
Head 3：在那里 <-> 北京
Head 4：吃了 <-> 烤鸭
```

多个 Head 可以同时从不同角度理解上下文

## 计算过程

​$N 个 Head 会并行计算 N 次独立的 Attention$​

```
                    输入 X
                      │
        ┌─────────────┼─────────────┐
        ↓             ↓             ↓
      Head 1        Head 2         ... Head 8
        │             │                 │
     Q1,K1,V1      Q2,K2,V2         Q8,K8,V8
        │             │                 │
   Attention 1   Attention 2       Attention 8
        │             │                 │
       O1            O2              O8
        └─────────────┼───────────────┘
                      ↓
                   Concat
                      ↓
                      Wo
```

## 局限性

输入的序列一旦过长，KV Cache 会过大，对资源占用过高，在推理时是一个很大的显存开销

​

# MQA(Multi-Query Attention)

少存一些 KV，但尽量不损失模型性能

​

## 为什么 KV Cache 是瓶颈

假设模型已经生成了 10000 个 token，有 8 个注意力头，每个注意力头的 d\_K = 64

在训练时：

每生成一个 token，就要存进去 $8*Q +8*K+8*V$​

在训练时通常不会出问题，因为训练时会把整个输入序列的 QKV 全部算完，只是用了 Mask 遮住未来的 token，保证模型看不到答案。但同时也会存储 QKV，只是不用 KV Cache 这一推理时的概念，而且训练时显存占用大头另有其人，存储 KV 只是其中之一，所以在训练时优化存储 KV 与否，影响不大

在推理时：

根据 MHA 中每一个 Query Head 都有自己独立的 KV

每生成一个 token，就要存储 $8*K+8*V$​

上下文越长，KV Cache 就越大

## 核心思想

多个 Query 共用一个 K 和 V

```
Q1 ─┐
Q2 ─┤
Q3 ─┤
Q4 ─┤
Q5 ─┤
Q6 ─┤──→ K,V
Q7 ─┤
Q8 ─┘
```

也就是说：

​$8*Q+8*K+8*V$→ $8*Q+1*K+1*V$​

因为尽管 KV 相同，但是 Q 还是不同，依然可以产生不同的注意力分布

​

## 省了多少？

如果是 MHA，N 个注意力头就要存储的数字为：

​$N * (d_K+d_V)*L$​

如果是 MQA，N 个注意力头就要存储的数字为：

​$（d_K + d_V）*L$​

​$L$ 为序列长度，也就是多少个 $k$向量和$v$向量

所以一般来说，MQA 是 MHA $1/N$的 KV Cache

## 局限

牺牲了一部分的表达能力，但带来了比较大的性能提升

​

# GQA

基于 MQA 平衡性能与速度

不再是 MQA 的多个 Query Heads 对应一个 K和 V

而是 多个 Q 对应 N 个 KV，只不过&#x20;

​$1<N<N_Q$​

​

​

# MHA、GQA、MQA 本质上对应不同程度的 KV 共享，在模型质量、KV Cache 和推理效率之间取得不同的平衡。

# 自述

先从 LLM 如何生成 token 说起，在训练时，整个训练序列一次性并行计算输入的所有 Q/K/V 和 Attention，使用 mask 来按住未来的 token防止看答案，因此可以在在所有 token 的位置同时开始训练，模型根据当前位置的 token 的 Q 结合前面已缓存的 KV 来计算下一个位置的隐藏状态，基于此预测下一个 token，同时也有多个注意力头做着并行计算，负责学习不同角度的关系与语义，最后 concat 来生成下一个 token，此时缓存的 KV 虽然占用显存但这只是占用较大的其中之一，但 KV缓存等保存的中间激活并不是训练阶段优化目标。但在推理时，为了避免重复计算，将历史 token 的 KV 存进 KVCache，因为历史 token 的 Q 在预测中不参与计算，所以不存储 ，但是 KVCache 的大小与上下文、KV 维度成正比，模型每次预测都要对之前的所以 token 进行注意力计算，而且在 MHA 中有 N 个注意力头每次生成 token 就要存进去 N 个 KV，所以这是一笔不小的显存开销。为了省下宝贵的显存资源，引入了 MQA，多个Q Head共用一个 KV，因为 Q 不同，所以也能得到不同的注意力分数。一般情况下MQA 是 MHA 的 1/N KVCache，MQA牺牲了一定的表达能力，换来了更低的显存占用与更快的生成速度。为了平衡速度与质量，引入 GQA，将 QHead 与 KV 的比例从 N：1 换为 N：M，M 是介于 1 和 N 之间的数。通过以上方式来加速 token 生成与降低显存占用，同时质量损失很小
